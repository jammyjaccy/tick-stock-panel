## 二. 请求纪律 (已验证有效, 后续必须沿用)

公网源被封是按 IP 封, 一次可能停数天. 本项目实测的规则:

```
1. 间隔      3.0 秒基础 + 0~1.5 秒随机抖动 (平均 3.75 秒)
2. 失败即停  403 / 429 / 5xx -> 立即终止整批, 不重试, 不换源
             404 单独处理 (当天无包), 跳过即可
3. 单批上限  不超过 60 次请求, 跑完停下评估再决定
4. 绝不逐只循环调接口; 盘后包是每交易日 1 个静态文件, 一天拉一次就够
```

实测: 累计约 65 次请求, 零 403 / 零 429 / 零 404.

## 四. 已确认的问题: 扶摇的北交所日K 量额偏小

39 只次异常的三条规律:

```
1. 100% 是北交所 (920xxx.BJ); 深沪主板/创业板/科创板 零异常
2. 方向 100% 一致: 盘后包 > 面板 (36/36 按量比口径), 没有一次反过来
3. 北交所内部异常率 39 / 18,879 标的日 = 0.21%; 全样本 0.0118%
```

缺口是整齐的整数块:

| 日期 | 标的 | 面板(手) | 盘后包(手) | 缺口(手) |
|---|---|---|---|---|
| 2026-10-19 | 920475 三友科技 | 5,039 | 10,039 | 正好 5,000 |
| 2026-06-30 | 920116 星图测控 | 37,355 | 54,616 | 17,261 |
| 2026-06-16 | 920175 东方碳素 | 69,156 | 77,157 | 8,001 |
| 2026-04-15 | 920599 同力股份 | 25,524 | 33,525 | 8,001 |

**归因: 扶摇在北交所漏了成交块, 不是盘后包的问题.** 面板现有北交所日K 的
成交量/额本来就偏小, 此前无跨源对拍, 未被发现. 未查证具体成因
(候选: 盘后固定价格交易 / 大宗交易 / 北交所逐笔口径差异).

**曾被推翻的猜测**: 早期只看到两例, 差额都接近 3,000 手, 一度判断为恒定模式.
60 天数据显示差额分布 300 ~ 17,261 手 (中位 1,590), 恒定 3,000 手 0/39 例.
两例接近是巧合.

## 五. 方法论陷阱: 面板"当天"分区会被重写

首次对拍 2026-11-17 时报告 4 只北交所异常, 同一份盘后包二次对拍变成 0 只.
原因不是数据源变动, 是面板自己在改:

```
23:27:41  行情服务 -> 最终行情同步开始
23:27:42  扶摇实时行情拉取完成: 5583 条
23:27:43  enriched 增量: 5573 只, 2026-11-17     <- 分区在此被重写
23:27:43  收盘 最终行情同步完成 (快照时间戳已达边界), 进入休盘态
```

首次读取时该分区装的还是收盘后未定版的快照数据.

**规则: 对拍必须在"最终行情同步完成, 进入休盘态"之后再跑**, 否则会把
"面板尚未定版"误判成"数据源不一致". 此条已导致一次完整误报.

## 六. 结论与用途

日K 这条路**可以接**, 但面板日K 已由扶摇覆盖, 因此真实价值在别处:

```
1. 金标准    -> 以后接任何新数据源, 用它做对拍基准 (已验证)
2. 免费备份  -> 扶摇不可用时作为替代日K 源
3. 更早历史  -> 盘后包从 2021-08-16 起 (但见下方限制)
```

### 限制: 补更早历史的价值不高

扶摇自身已有 **10 年全市场日K dump** (`fuyao/provider.py:79`
`_DAILY_DUMP_KIND = "daily-k"`, 约 172 MB, 一次下载覆盖全市场, 免费).
面板只是没回补那么长. 因此"用盘后包补更早历史"并非唯一途径, 且扶摇那条更省事.

## 七. 复现方式

```

compare60_host.py   宿主机对拍 (只需 pandas)
```

```bash
# 下载 (需 a-stock-data 的 venv)

  /home/workspace/a-stock-data/.venv/bin/python fetch60.py
```
