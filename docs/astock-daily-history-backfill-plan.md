## 1. 目标

把面板日K 从 **244 个交易日 (2025-11-17 起)** 延长到 **2021-08-16 起**
(通达信盘后包可提供的最早日期), 约再补 **1,030 个交易日**.

非目标:

- 不补分钟 (上限 320 根/只, 无批量, 已判否).
- 不换现有日K 数据源. 补历史只解决"回测太短", 当日增量仍走扶摇.
- 不碰 2025-11-17 及之后的现有数据.

## 2. 现状 (实测 2026-11-18)

```

kline_daily_enriched 244 天  244 文件       65 MB   (15 列, 含前复权 close / raw_close / 换手率 / 连板)
```

## 3. 供给侧事实

- 来源: 通达信官网盘后包, 一个交易日一个静态文件, 约 2.7 MB.
- 覆盖: 2021-08-16 起; 每包含沪深北全部证券 (含基金/债券/指数, 需过滤).
- 字段: `date, market, code, name, prev_close, open, high, low, close, volume, amount`.
- 价格: 与面板已有 244 天对拍 **100% 一致** (60 天逐标的, 见实测评测文档).
- 数量单位: volume **股**, amount **元**.
- 北交所: 包内有 (2025-11-17 样本: 294 条, 其中 920xxx 281 条).

## 4. 三个必须先解决的问题

### 4.1 北交所老代码 (P0 已实测, 仍需映射表)

P0 实测 (2026-11-18, 4 个包):

| 包日期 | 北交所行数 | 代码前缀 |
|---|---|---|
| 2023-06-15 | 201 | 43:16 / 83:148 / 87:36 / 89:1 |
| 2024-06-14 | 253 | 43:16 / 82:3 / 83:178 / 87:54 / 92:1 |
| 2025-06-16 | 274 | 43:15 / 82:7 / 83:172 / 87:54 / 92:25 |
| 2026-11-17 | 390 | 92:356 / 82:26 / 91:6 / 89:2 |

结论:

- 2025 年之前北交所基本是 43/83/87 老码; 920 迁移到 2026-11 才完成 (356 只全在新码).
- 补 2021-2025 北交所历史, **必须有新旧码映射**, 否则会写入孤儿代码.
- 可用的映射思路: a-stock-data 文档记录了迁移并给出"东财 push2 北交所清单按名称反查现行代码"
  (`SKILL.md:603-613`); 也可用包内 `name` 做跨年份匹配, 但要处理简称变更.
- 已确认: 2026-11-17 的 356 只北交所全部在新码段, 当前增量不受影响.

处置: 按 Jimmy 的决定, 映射做不出来就**只补沪深, 北交所历史另案**, 不猜映射.

### 4.2 除权因子历史 (P0 已实测, 两条路都通)

现在只有 2025-11-17 起的 4,957 条. 前复权 close 依赖除权事件,
没有因子就无法正确计算早期数据的前复权, 回测跨除权日会被假跌停打断.

**A 推导 (已验证)**: 用包内 `prev_close` 反推, `ex_factor = 前一日 close / 当天 prev_close`.

- 实测范围: 2026-11-11 -> 11-17 四个连续交易日, 限定 A 股.
- 结果: 推导出 **27 个事件, 与面板 adj_factor 完全一致 (0 漏, 0 多)**,
  最大相对误差 6e-5. 说明该方法与面板现有口径同源, 可直接用于历史.
- 不限定 A 股时多出的"事件"全部是基金/债券/指数分红, 过滤前缀即可.

**C stockdb (已验证可用)**: 本地 `复权` 表, 覆盖 1991 年起, 字段
`div / give / trans / mult / cum`.

- 与面板 4,957 条对拍: 日期命中 **4,626 条 (93.3%)**, 缺 331 条 (多为 2026-10 之后,
  说明 stockdb 因子更新滞后, 不能替代当前增量).
- 数值: 中位偏差 0.025%, p99 0.12%; 3 条偏差 >1% (最大 29.7%, 需单独核对).
  偏差来源是定义不同: stockdb 用理论公式, 面板用交易所除权参考价 (按最小价位取整).
- 有 `div/give/trans` 明细, 是 A 推导拿不到的信息.

**结论**: 事件日历和分红明细用 stockdb, `ex_factor` 数值用包价推导 (与面板口径一致),
两条互相校验; 331 条 stockdb 缺失但包内可推导的事件以包为准.
B 方案 (a-stock-data 逐只) 不采用.

## 5. 执行阶段

### 5.0 路线 B (2026-11-18 新发现, 待批量验证)

实测: 20:29 只查询了 600519 的 2021-08-16~08-20, 面板的 `daily_bootstrap.ensure_history`
自动按 `fetch_start = end - 365 天` 从扶摇 historical-batch 回补了 2020-08-20~2021-08-19,

- 未知: 扶摇 historical-batch 的单次标的上限, 长区间耗时与配额, 全市场历史深度.
- 待验证: 50 只 x 1 周 的受控测试 (会写约 250 行真实数据, 需批准).
- 已知副作用: "查询即补数"会让 `trading_days` 分区数虚高
  (当前 489 天里 245 天只有 600519 一只).

路线 A (通达信包) 与路线 B (扶摇) 的取舍, 等 B 的批量能力实测后再定.

### P2 分批补全 (约 1,030 天)

```
每批 60 个交易日 -> 下载 -> 校验 -> 落盘 -> 停 30 秒后评估 -> 下一批
403 / 429 / 5xx -> 立即停止整批, 不重试, 不换源
已落盘日期自动跳过 (可断点续跑)
```

预估: 下载约 2.8 GB, 请求约 1,030 次, 间隔 3~4.5 秒, **纯等待约 70~80 分钟**,
加上落盘与校验约 2 小时. 磁盘增量约 +800 MB (日K) + 280 MB (enriched).

## 6. 写盘约定

- 分区与现在同构: `kline_daily/date=YYYY-MM-DD/part.parquet`, 一个交易日一个目录.
- 列顺序/类型与现有 9 列完全一致; `quote_ts` 用包内收盘时间 (15:00 北京时间).
- 只写缺失日期; 已存在日期一律跳过, **绝不覆盖**.
- 写入用仓库现有 `atomic_write_parquet`, 避免半截文件.

## 7. 验收标准

1. `trading_days` 从 244 -> 约 1,274, 最早日期 2021-08-16.
2. 随机抽 30 个 (标的, 日期) 组合, close/volume/amount 与包逐条一致.
3. 相邻两日价格连续性: 跨新旧边界 (2025-11-14 -> 2025-11-17) 无异常跳空.
4. 除权因子对拍: 2025-11-17 之后与现有 4,957 行完全一致 (4.2 验收).
5. P4 基线不变.

## 8. 风险与回滚

| 风险 | 处置 |
|---|---|
| 历史包缺失某天 (节假日/未发布) | 跳过并记录, 不伪造; 最终报告缺天清单 |
