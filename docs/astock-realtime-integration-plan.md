## 0. 结论 (先看这段)

a-stock-data 能补面板最贵的两块实时数据:

1. **五档盘口** - 现在只有涨跌停个股需要拉五档, 走 TdxQuant, 按积分计费. 腾讯原始快照字段 9-28 含五档 (a-stock-data 的 `tencent_quote()` 没有解析), 免费.
2. **实时快照与指数** - 现在走 fuyao, 每轮 1 个请求. a-stock-data 走腾讯 quote, 免 Key, 但每轮需要 7 个左右的分批请求.

它**不是**一个可以直接 import 的 SDK: 代码内嵌在 7702 行的 `SKILL.md` 里, 自带的 `tencent_quote()` **不返回成交量, 时间戳和五档**, 必须自写原始字段解析. 分钟 K **不建议接**: 没有成交额, 北交所无数据, 241 根/日, 最新交易日成交量还是整手.

推荐顺序:

```
M0  只读实测 (公网探测, 不动面板)
M1  五档盘口        <- 收益最大, 风险最小
M2  实时快照        <- 必须先解决标的池与全市场覆盖
M3  分钟 K          <- 不做, 保持 TdxQuant 单只按需
```

**M0 未跑之前, 不建议写任何插件代码.** 本方案里最关键的三个未知数 - 腾讯单次批量上限, 五档字段单位, 北交所覆盖 - 都只能靠实测回答.

## 1. 面板对实时数据的硬性要求

### 1.1 能力与路由

| 能力 | 现状 | 证据 |
|---|---|---|
| 实时行情 | fuyao, 6 秒轮询 | `docs/decisions.md:53-54` |
| 五档盘口 | TdxQuant, 默认 10 秒轮询 | `depth_service.py:47-57`, `preferences.py:699-701` |
| 分钟 K | TdxQuant, 批量同步已关闭 | `docs/handoff.md:90-96` |
| 指数 | 核心四只 + 基准指数, 随实时轮询拉取 | `index_const.py:12-20`, `pipeline.py:1141-1144` |

自定义源的实时契约是**全市场快照**, 不是按需报价 (`docs/decisions.md:42`). 新增数据源只声明 `datasets`, 不改 service (`docs/plugin-development.md:1-7`).

### 1.2 轮询与性能

| 项 | 要求 | 证据 |
|---|---|---|
| 默认间隔 | 6 秒 | `quote_service.py:283` |
| 自定义源下限 | 1 秒 | `quote_service.py:282` |
| 上限 | 60 秒 | `quote_service.py:284` |
| 拉取方式 | fetch 锁串行, 不允许并发重叠 | `quote_service.py:829-843` |
| 热路径约束 | 不得在线性于历史数据量的循环里; 不得逐只请求 | `CONTRIBUTING.md:199-203` |
| 失败语义 | `get_realtime` 软失败返回 `[]`, 不抛异常 | `plugin-development.md:299-303` |

### 1.3 字段与单位契约

| 字段 | 要求 | 证据 |
|---|---|---|
| `symbol` | 带交易所后缀, 如 `600519.SH` | `plugin-development.md:104-107` |
| `volume` | **手**, 1 手 = 100 股 | `plugin-development.md:109-117` |
| `amount` | 元 | 同上 |
| `change_pct` | **小数制**, `0.0366` = 3.66% | 同上 |
| `turnover_rate` | 入口小数制, enriched 内部百分数 | `CONTRIBUTING.md:86-96` |
| `timestamp` | 毫秒, 优先服务端时间 | `plugin-development.md:343` |
| `amplitude` / `turnover_rate` | 接口不提供就置 `None`, 禁止启发式补全 | `plugin-development.md:119-124` |
| 五档量 | 手 | `CONTRIBUTING.md:98` |
| 分钟 `datetime` | 北京墙钟 naive, 09:31-15:00, 240 根/日 | `plugin-development.md:255-263` |
| 分钟 `amount` | 无可靠值必须 `null`, 不得伪造 | `plugin-development.md:262` |

### 1.4 时间归属与收盘定版

实时记录会写进当天 `kline_daily` 分区. 写盘前有两道硬门:

1. `quote_ts` 的北京日期必须等于今天, 否则该行被丢弃. 停牌股返回旧时间戳正是靠这条挡住的 (`quote_service.py:1241-1252`).
2. 收盘定版要求本轮快照最大 `timestamp >= 15:00:00 - 5 秒` (午盘是 11:30), 未达到则只更新展示缓存, 不落盘 (`quote_service.py:55-61`, `1097-1141`).

因此数据源必须给出**真实的服务端时间戳**, 不能用本地时间伪造. 缺时间戳的源会让定版逻辑失效.

### 1.5 全市场覆盖 (最容易被低估的一条)

实时行情写当天分区用的是**覆写**语义, 不是 merge:

```python
# backend/app/tickflow/repository.py:2777-2802
def flush_live_daily(self, df):
    """覆写当天 kline_daily 分区 (实时行情落盘, 非merge)."""
```

含义: 数据源这一轮少返回哪些标的, 当天分区里就没有哪些标的. 不是"保留旧值", 是直接消失. 所以接实时源的第一验收项不是价格准不准, 而是**覆盖率**.

实测面板标的池 (2026-11-17 分区):

```
总计 5,573 只   深市 2,903   沪市 2,314   北交所 356
```

a-stock-data 必须覆盖这 5,573 只, 不能只覆盖沪深.

### 1.6 指数契约

核心四只固定, 不走路由矩阵 (`index_const.py:12-20`):

```
000001.SH 上证指数   399001.SZ 深证成指
399006.SZ 创业板指   000680.SH 科创综指
```

另外需要基准指数 `399107.SZ`, `399102.SZ`, `899050.BJ` (北证50) 供偏离值计算 (`pipeline.py:1135-1144`). 插件实现可选的 `get_realtime_indices(symbols)`, 失败返回 `None` 保留上轮缓存 (`plugin-development.md:190-194`).

### 1.7 五档契约

五档服务只拉**已涨停/跌停**的个股, 不是全市场 (`depth_service.py:210-300`):

```
batch 默认 100 只, rpm 默认 30
轮询间隔硬下限 10 秒, 默认 10 秒
单批失败隔离, 不跨源回退
```

返回结构: `bid_prices` / `bid_volumes` / `ask_prices` / `ask_volumes` / `timestamp`, 量单位手, 时间戳毫秒 (`plugin-development.md:214-228`).

这意味着五档的请求量很小: 100 只涨跌停 = 每 10 秒 1 个请求.

### 1.8 部署形态

- 面板跑在容器 `tsp`, 数据目录是宿主机 `/home/workspace/tickflow-data` (`docs/handoff.md:15-34`).
- 外部插件 ZIP 安装到 `data/plugins/<name>/versions/<version>/`, 持久化在挂载目录, 重启和升级主程序都不会覆盖 (`external-data-source-packages.md:24`).
- 容器 venv 实测有 `httpx 0.28.1`, `polars 1.44.1`, `pandas 3.0.3`, **没有 `requests`**. 插件不要依赖 `requests`.
- 外部插件与后端同权限, 不是沙箱 (`external-data-source-packages.md:9`).

## 2. a-stock-data 供给侧事实

### 2.1 形态与许可

| 项 | 事实 |
|---|---|
| 形态 | 单个 `SKILL.md` (7,702 行), Python 代码内嵌在 Markdown 代码块里 |
| 版本 | v3.10.4 |
| 许可 | Apache-2.0 |
| 可 import | **否**. 没有 `pyproject.toml` / `setup.py` / 包名 |
| 调用方式 | 从 `SKILL.md` 抽取代码块执行, 或复制函数到自己的脚本 |
| 依赖 | 文档写 `mootdx requests pandas stockstats numpy baostock xlrd openpyxl`; 实时 quote 路径本身只用 stdlib `urllib` |
| 遥测 | 未发现 |
| Key | 腾讯 quote / K 线 / 指数均不需要 Key |

结论: 接入方式是**抽代码 + 自写适配**, 不是 `pip install`. 复制 Apache-2.0 代码时保留版权与 NOTICE 声明.

### 2.2 实时快照 `tencent_quote`

位置: `a-stock-data/SKILL.md:1072-1147`.

```
GET https://qt.gtimg.cn/q=sh600519,sz000001,...
响应 GBK 解码, 每行按 ~ 切分
```

输入限制:
- 只接受 6 位数字或显式 `sh` / `sz` / `bj` 前缀.
- **不接受** `600519.SH` 这种后缀格式 (`SKILL.md:619-625`).
- 不带前缀的 `000001` 会被路由成 `sz000001` (平安银行), 不是上证指数 (`SKILL.md:595`).
- 一次 GET 发完整列表, 代码里**没有分批, 没有 URL 长度保护**; 单次能放多少只未验证.

返回值 (实际暴露的 key):

```
name, price, last_close, open, change_amt, change_pct, high, low,
amount_wan, turnover_pct, pe_ttm, amplitude_pct, float_mcap_yi,
mcap_yi, pb, limit_up, limit_down, vol_ratio, pe_static, is_stale
```

**关键缺口**:

| 面板必需 | tencent_quote 是否提供 | 后果 |
|---|---|---|
| `volume` | **否** | 必须自己解析原始字段 |
| `timestamp` | **否** (字段 30 被丢弃) | 必须先解析, 否则收盘定版失效 |
| 五档 | **否** (字段 9-28 未解析) | 必须自己解析 |

所以 `tencent_quote()` 只能作为字段含义的参考, 不能直接作为 provider 实现.

### 2.3 原始字段表 (腾讯 quote)

a-stock-data 文档确认的字段:

| 下标 | 含义 | 单位 |
|---|---|---|
| 1 | 名称 | - |
| 3 | 最新价 | 元 |
| 4 | 昨收 | 元 |
| 5 | 今开 | 元 |
| 9-18 | 买一~买五 (价+量成对) | 未验证 |
| 19-28 | 卖一~卖五 (价+量成对) | 未验证 |
| 30 | 时间 `YYYYMMDDHHMMSS` | 北京墙钟 |
| 31 | 涨跌额 | 元 |
| 32 | 涨跌% | 百分数 |
| 33 / 34 | 最高 / 最低 | 元 |
| 35 | `最新价/成交量/成交额(元)` | 成交量: 科创板股, 其余手 |
| 37 | 成交额 | **万元** |
| 38 | 换手率 | 百分数 |
| 43 | 振幅 | 百分数 |
| 58 | 盘后定价成交额 | 万元 |

字段 35 是成交量与成交额最可靠的入口: a-stock-data 自己的 `_tencent_qt_snapshot` 就用它取成交额, 并明确写了"科创板成交量是股, 其余是手" (`SKILL.md:1566-1568`).

### 2.4 指数

没有独立指数端点, 走同一个 `tencent_quote`. 必须显式传前缀:

```
000001.SH -> sh000001
399001.SZ -> sz399001
399006.SZ -> sz399006
000680.SH -> sh000680
399107.SZ -> sz399107
899050.BJ -> bj899050  (北证50, 腾讯是否支持未验证)
```

沪深指数覆盖没问题; 北交所指数未验证 (`SKILL.md:7305-7308` 只覆盖北交所个股五档).

### 2.5 分钟 K

`tencent_kline(code, period="m1", count<=320)`:

- **逐只**, 没有全市场批量 (`SKILL.md:1268-1277`).
- 最多 320 根, 约 1.3 个交易日.
- **只支持沪深**, 北交所直接抛错 (`SKILL.md:1197-1199`).
- 没有成交额列; 第 8 个数组字段是换手率, 不是成交额 (`SKILL.md:1205-1210`).
- 每天 241 根, 09:30 那根只含开盘集合竞价 (`SKILL.md:1217-1219`).
- 成交量: 科创板是股, 其余是手; 最近一个交易日是整手, 下一交易日才回填精确股数 (`SKILL.md:1206-1216`).

面板要求 240 根/日, 09:31-15:00, 且 `amount` 缺失时前端会停止画均价线 (`plugin-development.md:255-263`). 两边口径差一条街, 不是配置能解决的.

### 2.6 五档

- 文档只写了 9-18 是买一~买五 (价+量), 19-28 是卖一~卖五 (价+量) (`SKILL.md:1169-1170`).
- 代码**没有解析**, 也没写每对里谁先谁后, 量是手还是股.
- 北交所另有官方五档 `bse_quote_backup()`, 量明确是股 (`SKILL.md:7305-7308`).
- mootdx 的五档命令自 2026-09 起返回 0 行 (`SKILL.md:564-566`).

结论: 五档字段顺序按公开惯例大概率是 `价, 量, 价, 量...`, 但**必须盘中实测**, 且要和 TdxQuant 同一时刻对拍.

### 2.7 限流与封禁

- 腾讯 quote 代码里**没有节流, 没有重试, 没有状态码检查** (`SKILL.md:1099-1103`).
- 文档声称腾讯 quote "不封 IP", 但同时建议控制频率, 没有给出阈值 (`SKILL.md:337`, `343`).
- 腾讯 K 线单入口约 600 次后返回空 JSON, 换入口可恢复 (`SKILL.md:1197-1198`, `1230-1234`).
- 东财才是真正的封禁重灾区: 实测 10 线程 1 小时 45,000+ 请求, IP 级封禁 20+ 小时 (`SKILL.md:363-373`). 本方案不碰东财.
- 工具包自带的 `EM_SESSION` / `V39_RETRY_SESSION` 会**自动重试 429**, 与项目"失败即停"的纪律冲突; 不要复用 (`SKILL.md:765-778`, `833-847`).

### 2.8 全市场代码表

a-stock-data 的腾讯 quote 不提供"全市场代码列表". 可用的全市场清单来源是通达信盘后包:

```
tdx_daily_package(date)  ->  沪深北全部证券当日日线
下载约 2.7 MB, 一个交易日一个文件
个股 volume 单位股, amount 单位元
非交易日 / 当天包未发布 -> ValueError
```

证据: `a-stock-data/SKILL.md:1400-1500`.

这个包同时给了代码, 名称, 市场, 昨收. 但它包含债券, 基金, 北交所旧代码, 需要按 A 股前缀过滤, 过滤结果未必与面板标的池完全一致.

## 4. 目标架构

### 4.1 形态

外置插件, 不改核心:

```
astock.zip
├── plugin.yaml
├── provider.py        # 路由与契约
├── client.py          # HTTP + 原始字段解析 + 限流
├── mapping.py         # 代码/单位/时间映射 (纯函数, 好测)
└── README.md          # 覆盖范围与已知限制
```

`plugin.yaml` 关键字段. **M1 只声明 `[depth5]`**, 避免还没过覆盖率就被人切到实时; M2 验收通过后再加 `realtime`:

```yaml
name: astock
version: 0.1.0
plugin_api_version: 1
display_name: "a-stock-data (腾讯行情)"
runtime: none
entry: provider:AstockProvider
datasets: [depth5]          # M2 验收后改为 [depth5, realtime]
requires: ["httpx>=0.27"]
requires_app: ">=0.3.37"
requires_python: ">=3.11"
description: |
  免费腾讯行情. 当前只接管五档; 实时快照需通过覆盖率验收后再启用.
usage_notes:
  - "五档: 仅涨跌停个股, 免费, 建议保持 10 秒"
  - "M2 实时快照: 分批请求, 全市场一轮约 7 个请求; 建议轮询间隔 >=30 秒"
```

不声明 `minute` / `full_minute` / `daily` / `financial`. 声明了就会接管整条链路, 回退不回来.

外部包约束 (`external-data-source-packages.md:55-59`): 用相对导入 (`from .client import ...`), 不改 `sys.path`, 不写程序目录; 构造函数快速且不联网, 取数在数据方法里做; 必须实现 `close()`. 需要异常类型时从公开契约 `app.data_providers.base` 导入, 不碰 service 私有属性.

### 4.2 数据流

```
QuoteService (6s/30s)
  -> provider.get_realtime()
       -> client.quote_batch(symbols)  [N 个 HTTP GET, 3s 间隔]
       -> mapping.to_realtime_records()
  -> _process_full_market_records()
       -> 覆写当天 kline_daily / enriched

QuoteService
  -> provider.get_realtime_indices(core4 + benchmarks)
       -> 同一 client, 显式前缀

DepthService (10s)
  -> provider.get_depth_batch(limit_up_down symbols)
       -> client.quote_batch(chunk) -> 解析字段 9-28
```

### 4.3 不改核心

现有 provider 契约已经覆盖 realtime / depth5 / indices, 不需要改 `quote_service.py` 或 `depth_service.py`. 唯一可能需要核心配合的是"标的池" (见第 6 节).

## 5. 字段映射与单位 (实现的核心)

### 5.1 代码映射

| 内部 symbol | 腾讯 code | 规则 |
|---|---|---|
| `600519.SH` | `sh600519` | 沪市 6 开头 |
| `000001.SZ` | `sz000001` | 深市 0/3 开头 |
| `920475.BJ` | `bj920475` | 北交所 92 开头 |
| `000001.SH` | `sh000001` | **指数必须显式 sh** |
| `399001.SZ` | `sz399001` | 指数显式 sz |
| `899050.BJ` | `bj899050` | 北证50, 待验证 |

禁止把带后缀的 symbol 直接传给腾讯; 必须先在插件内转换.

### 5.2 实时记录

| 内部字段 | 来源 | 转换 |
|---|---|---|
| `symbol` | 请求时的内部 symbol | 原样回填 |
| `last_price` | 字段 3 | float |
| `prev_close` | 字段 4 | float |
| `open` | 字段 5 | float |
| `high` | 字段 33 | float |
| `low` | 字段 34 | float |
| `volume` | 字段 35 第 2 段 | 科创板 `688/689` 为股 -> `/100`; 其余已是手 |
| `amount` | 字段 35 第 3 段 | 元, 直接透传 |
| `change_amount` | 字段 31 | float |
| `change_pct` | 字段 32 | **`/100`** -> 小数制 |
| `timestamp` | 字段 30 | `YYYYMMDDHHMMSS` -> 北京时区 epoch ms |
| `name` | 字段 1 | 可选 |
| `amplitude` | - | `None`, 让 enriched 用 OHLC 算 |
| `turnover_rate` | - | `None`, 让 enriched 用历史股本算 (CONTRIBUTING §3.4) |
| `session` | - | `None` |

`amplitude` / `turnover_rate` 不取腾讯的百分数字段, 理由: enriched 内部口径是小数振幅和历史股本换手, 直接采用腾讯值会绕开 §3.4 的历史股本规则.

### 5.3 五档

按公开惯例解析 `9-18` / `19-28` 的"价, 量"成对字段, 但必须用实测确认:

- 买一价/量是否从 9/10 开始交替.
- 量单位: 非科创板是否手, 科创板是否股.
- 时间戳: 用同一行的字段 30, 不取本地时间.

返回结构与 TdxQuant 保持一致:

```python
{
  "600519.SH": {
    "bid_prices": [1500.0, ...],
    "bid_volumes": [10, ...],      # 手
    "ask_prices": [1500.1, ...],
    "ask_volumes": [12, ...],      # 手
    "timestamp": 1788505200000,    # ms
  }
}
```

### 5.4 缺失与异常

- 字段缺失 -> `None`, 不填 0, 不猜.
- 整批所有行都识别不出代码 -> 返回 `[]` + warning, 不静默成功.
- `v_pv_none_match` / 空行 -> 该代码跳过.
- 单个代码失败不拖垮整批; 整批失败返回 `[]`.
- 停牌股保留其旧时间戳, 交给核心的 `quote_ts` 日期过滤, 不在插件里判断"停牌".

## 6. 标的池与覆盖率 (M2 的前置条件)

### 6.1 问题

面板的实时写盘是**覆写当天分区**. 少返回一只, 当天这只就没了. 所以插件必须知道面板的完整标的池, 而且必须一只能不少地报回来.

### 6.2 三个选项

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 读本地分区 | 读 `data/kline_daily` 最新分区的 `symbol` 列 | 与面板标的池**完全一致**, 不改核心 | 依赖面板存储布局; 外部插件跨层读数据目录 |
| B. 通达信封包 + 前缀过滤 | 每天拉 2.7MB 盘后包, 按 A 股前缀筛 | 用工具包自己的能力, 不碰面板 | 含债券/基金, 前缀过滤可能多算或漏新股; 当天包收盘后才有 |
| C. 小改核心传入 | `get_realtime(symbols=...)` 由 quote_service 传标的池 | 架构最干净, 通用能力 | 碰 `quote_service.py` 高频文件, 需补契约与测试 |

**推荐 A 作为试点**, 把读取封装在 `client.load_universe()` 一个函数里, 失败时回退 B. 如果后续要长期跟随上游, 再升级到 C.

### 6.3 ETF 的坑

实测面板的 `instruments_etf` 目录为空, `get_etf_instruments()` 返回空表. 这意味着:

- 任何 ETF 实时记录都会被 `_process_full_market_records` 当成**股票**, 写进 `kline_daily`.
- `get_realtime_symbols(asset_type="etf")` 不要返回数据, 返回 `[]`.
- 在 ETF 维表补齐之前, 本插件只做股票 + 指数.

这是面板现有缺口, 不是本方案引入的.

### 6.4 验收线

```
覆盖率 = 插件返回的股票 symbol 集合 / 面板当天 kline_daily symbol 集合
要求 >= 99.9%, 且不得多出面板没有的 symbol
北交所 356 只必须在内
```

## 7. 轮询与限流

### 7.1 请求预算

假设单批 800 只, 5,573 只全市场:

| 轮询间隔 | 每轮请求 | 每分钟请求 |
|---|---|---|
| 6 秒 | 7 | 70 |
| 15 秒 | 7 | 28 |
| 30 秒 | 7 | 14 |
| 60 秒 | 7 | 7 |

五档另有: 100 只涨跌停 = 1 请求/10 秒 = 6 请求/分钟.

### 7.2 与"3 秒纪律"的调和

前期实测验证过的公网纪律是: 请求间隔 3 秒, 403/429 立即停, 单批不超过 60 请求 (`astock-data-verification.md:29-41`).

在这个纪律下, 7 个请求一轮至少要 21 秒. 所以:

- **a-stock-data 做实时主源时, 轮询间隔建议 30 秒, 不是 6 秒.**
- 6 秒轮询只适用于单请求源 (fuyao 现在就是 1 请求/轮).
- 五档的 1 请求/10 秒天然满足 3 秒纪律.

如果 M0 证明腾讯单批能稳定吃下 2,800 只 (URL 约 25KB), 请求数降到 2, 才值得讨论 6-10 秒轮询.

### 7.3 失败策略

```
403 / 429 / 5xx  -> 本轮立即放弃, 返回 [], 不重试, 不换源
超时            -> 同上
空响应 / 行数不足 -> 本轮放弃, warning 日志
连续失败        -> 跨轮指数退避 (30s -> 60s -> 120s), 只告警不自动切源
```

不复制 a-stock-data 自带的 429 重试 session.

### 7.4 观测

每轮打一条日志: 请求数, 总耗时, 返回行数, 缺失数, 最大/最小 quote_ts. 这是后续判断"能不能提速"的唯一依据.

## 9. M2: 实时方案

### 9.1 组件

| 方法 | 行为 |
|---|---|
| `get_realtime()` | 读标的池 -> 分批 quote -> 转 records; 失败返回 `[]` |
| `get_realtime_indices(symbols)` | 显式前缀映射; 失败的代码跳过; 整批失败返回 `None` |
| `get_realtime_symbols(symbols, asset_type)` | 补拉自选/详情; `etf` 返回 `[]` |
| `test_dataset("realtime")` | 取 3-5 只有界样本, 返回 rows/columns/preview |

### 9.2 收盘定版

- 字段 30 必须解析成毫秒, 且用北京时区.
- 15:00 后首次定版轮, 最大时间戳应 >= 15:00:00.
- 若腾讯在 15:00 后仍返回 14:59:xx, 定版会重试到 15:30; 必须在 M0 观察 15:00-15:05 的时间戳行为.
- 盘后固定价格交易 (15:05-15:30) 是否改变字段 35 的量, 必须实测; 若改变, 定版取 15:00 那一轮, 不取 15:05 之后.

### 9.3 与 fuyao 的差异

| 项 | fuyao | a-stock-data |
|---|---|---|
| 每轮请求 | 1 | 约 7 |
| 建议间隔 | 6 秒 | 30 秒 |
| 成交量 | 股 -> 手 | 字段 35, 科创板特殊 |
| 时间戳 | 服务端 | 字段 30 |
| 五档 | 无 | 有 |
| 指数 | 独立端点 | 同一端点 |
| Key | 需要 | 不需要 |
| 429 风险 | 有配额 | 腾讯未验证 |

结论: **fuyao 更适合做实时主源**; a-stock-data 做备用, 或者接受 30 秒刷新后再切主源. 五档则相反, a-stock-data 更适合.

## 10. M3: 分钟方案 (建议不做)

不做的理由:

1. 没有成交额 -> 面板分时图的均价线会消失 (`plugin-development.md:262`).
2. 北交所完全没有分钟数据 (`SKILL.md:1197-1199`), 面板有 356 只北交所.
3. 241 根/日, 09:30 是集合竞价, 与面板 240 根/09:31 起不一致, 需要丢/并首根, 口径要另行验证.
4. 最新交易日成交量是整手, 下一交易日才回填精确股数; 盘中拿到的量不是精确值.
5. 逐只请求, 无法全市场回补; 声明 `minute` 后, 一旦有人打开 `minute_sync_enabled`, 会变成灾难.

如果以后一定要接:

- 只声明 `minute`, 声明 `minute_history_days = 1`.
- `get_minute` 加硬守卫: `len(symbols) > 5` 或窗口超过 1 个交易日 -> 抛 `ProviderRequestError`, 明确拒绝批量.
- `minute_sync_enabled` 保持 `false`, 并在文档里写明本插件不支持历史批量.
- 只用于单只分时图, 接受无均价线.

即使这样, 也不如继续用 TdxQuant 单只按需 (1-2 分/只) 划算, 除非积分余额是硬约束.

## 15. 待决策 (Jimmy 拍板)

### 15.1 实时刷新间隔: 30 秒还是 6 秒

- **30 秒**: 符合 3 秒请求纪律, 7 个请求/轮, 风险低. 可见效果: 侧栏指数条和异动监控每 30 秒更新一次; 放量类规则的判定粒度变粗.
- **6 秒**: 需要单批 2,800 只以上, 或 7 个请求不间隔. 可见效果: 刷新跟现在一样快, 但腾讯限流未知, 可能整轮失败.

建议: 先用 30 秒做备用源; 只有 M0 证明大批量稳定, 再考虑提速.

### 15.2 实时源的角色

- **fuyao 主 + a-stock-data 备**: 保持 6 秒, 五档免费. 可见效果: 日常无变化, 只省五档积分.
- **a-stock-data 主 + fuyao 备**: 30 秒刷新, 不再依赖 fuyao Key. 可见效果: 刷新变慢, 覆盖率风险由新源承担.

建议: 先做第一种.

### 15.3 标的池来源

- **A 读本地 kline 分区**: 覆盖最准, 不改核心, 依赖存储布局.
- **B 通达信封包 + 前缀过滤**: 不碰面板, 可能多算基金/债券或漏新股.
- **C 小改核心传入**: 最干净, 但改 `quote_service.py`, 与 fork 的"避免高频文件"约定冲突.

建议: A 试点, 失败回退 B; 不轻易动 C.

### 15.4 分钟是否接

- **不接**: 分时图继续走 TdxQuant, 1-2 分/只, 有均价线.
- **接**: 免费, 但无均价线, 北交所无分时, 批量能力不可用.

建议: 不接.
